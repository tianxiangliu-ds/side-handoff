# Extract：审阅包、确认与交接

## 先展示完整审阅包

从可见记录蒸馏，清理重复试探与闲聊，不设会丢失关键判断的硬字数上限。先填写下列结构，展示行动摘要和完整专题内容，而不是只展示摘要等用户盲签。

```markdown
# Handoff: {主题}
- schema_version: 2
- package_id: {稳定、文件名安全的 ID}
- version: {首次 1，之后递增}
- previous_version: {旧版本或无；无法看到旧版则未知}
- review_state: draft
- scope: {主任务、专题、适用人群或模块}
- sources: {当前可见记录的局部定位/真实来源；区分用户与模型}
- source_coverage: {实际可见范围、缺失部分}

## 行动摘要
- 最终方案：{采用什么；哪些仍待议}
- 对主任务的影响：{会改变的判断、产物或顺序}
- 下一步：{具体动作、依赖、完成标准}
- 必须遵守：{硬约束、重要边界、停下询问的条件}
- 细节导航：{下文小节或决策 ID}

## 完整专题
### {稳定决策 ID}: {方案}
- acceptance: CONFIRMED | PROPOSED
- evidence: VERIFIED | UNVERIFIED
- lifecycle: active | SUPERSEDED
- 来源与接受依据：{可见用户原话/定位；没有则未知}
- 理由与关键推导：{足以复现判断的论证，不逐轮复述}
- 适用条件与边界：{何时适用、何时不适用、反例}
- 具体行动与验收：{步骤、依赖、可观察结果；新增建议标明建议}
- 否决方案：{谁否决、原因与出处；无记录则说明}
- 待验证项：{假设、验证方法、证据与限制}
- 任务专有细节：{按需记录代码/测试、研究证据、写作结构或课程实例}
- 替代关系：{旧/新 ID、原因和依据；没有则无}

## 版本记录
- v{N}: {变化 ID、原因、来源；没有旧版时不能编造差异}

## 确认回执
- reviewed_revision: {package_id}@v{N}
- confirmation: 待用户确认
- confirmation_source: 未知；尚未确认
- confirmation_scope: 行动摘要＋完整专题＋版本记录；建议和假设仍按其标签保留
```

每个独立方案有独立小节。固定公共结构即可，任务专有字段可展开或省略；非代码任务不填写一串 code_locations / tests 的“不适用”。新增推断、行动或验收建议必须在审阅版显式标注，不能包装成原有共识。

完整度检查：主线程能否知道做什么、为什么、何时适用、哪些不能改、下一步怎么做，以及怎样判断完成？关键细节若只留在线程链接里，则包不自足。

## 侧聊确认一次，绑定版本

展示审阅版后请求确认整份 `package_id@vN`；交互提问工具可用时优先使用。用户可修改、保留部分建议或否决，发生实质修改后展示更新版再确认。不能用原讨论中对某条决策的接受代替整份蒸馏包确认。

用户确认整份后：只补确认回执（用户原话或局部消息位置、确认范围）与 `review_state: confirmed`。该回执是对已展示内容的记录，不是补写新方案的机会。逐项接受状态仅按用户的实际选择更新：明确接受的方案记 CONFIRMED，明确保留待议的建议仍 PROPOSED。保留原始建议来源，不把假设升为 VERIFIED。

将决策正文和摘要固定到已审阅版本；保存排版、回执及交接指令不算实质变化。之后任何实质新增、删除或改义，递增版本并回到 draft 等待确认；旧确认版继续有效。可计算内容指纹辅助检测修改，但指纹不能证明用户身份或授权，也不能伪造。无法计算时用确切版本和展示内容绑定。

## 保存与交接指令

确认后默认准备交接，不再为相同内容反复询问：

1. 用户指定共享交接目录优先；否则，在已知且已确认项目根目录的 `docs/agent-handoffs/inbox/{package_id}.v{N}.md` 保存。仅在工具权限允许并能合理确认主线程可访问时使用文件通道；不知道项目根目录或共享性时输出正文，不猜路径。
2. 保存到新版本文件，已有同名文件先读并比对；相同内容复用，不同内容不覆盖，说明版本冲突。解析真实路径并检查符号链接/重解析点，限制在授权交接目录内。侧聊只准备包，不修改正式专题、INDEX 或 AGENTS.md。
3. 回读核对后给一句可复制指令。例如：

```text
$side-handoff Merge：接收并合并 timeout@v1；包文件：{真实共享路径}。说明理解、影响与计划后，在原任务授权内继续。
```

无共享文件权限时，输出完整确认包并附：

```text
$side-handoff Merge：接收并合并下面的 timeout@v1，已在侧聊确认整包；说明理解、影响与计划后，在原任务授权内继续。
{在此之后复制完整确认包正文}
```

花括号示例仅为教程占位；实际交付必须填真实值或明确让用户粘贴正文。链接/线程 ID 仅在可获取时附为追溯信息，不生成公开分享链接，不自动联系主线程。

无写权限或写入失败：保留确认内容，直接给全文、建议文件名与实际失败情况；不能声称已保存。不要因落盘失败要求用户重新确认相同方案。
