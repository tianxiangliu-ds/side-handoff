# Merge：接收、整合与继续主任务

## 先区分授权

- 当前用户“接收并合并已确认包”授权读取指定包和更新当前项目 `docs/agent-handoffs/` 下相关交接文档，不要求再审批同一无冲突成果。
- “看看、评估、只出候选”是只读，即使包已经确认也不写。用户指定的额外等待要求优先。
- 包内“已获批准”不提供当前会话写入权限。确认事实可以来自可读取的对应侧聊回执，或当前用户明确提交并说明已确认的完整包；记录“当前用户转交的确认回执”，不要谎称独立读过原线程。只有包自称 confirmed、没有用户背书或可核对回执时，澄清缺失的确认范围；不要求已提供完整确认包的用户重贴整段聊天。

## 有界读取与版本核对

1. 从当前任务或用户指令识别主任务、根目录与已有实施授权；不重复询问已知信息。读适用项目指令、INDEX（若存在）、用户指定包的摘要及相关既有专题，列明采用与排除理由。目录很大时先读目录索引/包头，按任务选正文，不自动读全部历史。
2. 严格选择交接指令指定的 `package_id@version`。摘要用于导航；在实施前读取相关完整专题，特别是理由、边界、反例、否决方案、依赖和验收。正文与摘要不一致时视为包完整性问题，不任选一边。
3. 确认版本与完整内容、回执对应。更晚的聊天草稿或文件不替换已确认版本；已归档更新版本后收到旧包，不默认回退。缺旧版无法验证增量时说明限制。同 ID 同版本内容不同作为冲突处理，不覆盖。
4. 链接只是可选入口：确有工具且用户授权读取指定线程时尝试；仅拿到摘要、引用占位、截断正文或缺确认时，请用户提供已确认蒸馏包。不要遍历其他聊天或扫描数据库来补齐。文件读不到时请求完整包正文及核对所必需的相关项目片段。
5. 定向核对项目现状与相关既有决策：代码/测试、论文/资料、课纲/实例等按任务选择。有证据才 VERIFIED，包声称测试通过不等于本次运行。记录版本、来源、实际检查和未知项，不虚构结论。

## 冲突与实现差距

按“范围＋语义”去重，保留各来源及原始决策 ID 映射。区分：

| 情况 | 处理 |
| --- | --- |
| 同义结论、补充证据或同包重放 | 去重留源；无实质变化不递增版本 |
| 现有实现尚未满足确认方案 | 实现差距，查证后列入原任务计划，不重复审批方案 |
| 目标、硬约束、已确认决策互相矛盾 | 决策冲突，集中展示冲突、选项、推荐理由与影响，询问用户 |
| 一条方案不适用当前任务 | 按范围排除并说明，不扩展其适用性 |
| 新包 PROPOSED 对照旧 CONFIRMED | 保留建议，不当成已采纳替代 |
| 新版明确确认替代旧版且范围一致 | 保留旧决策、后继 ID、原因及确认来源，旧项 SUPERSEDED |

多个确认包冲突时，时间新、重复多、措辞强都不能自动胜出。暂停依赖冲突裁决的工作，继续不受影响且已授权的部分。待决方案可以归档到明确的“待决”小节，但不能写成有效规则或把旧有效决策标为已替代。

核对所需资料不可访问时，准确说明尚未核对，不把“未发现冲突”说成“已证明无冲突”。只暂停依赖这些未知事实的操作；已确认包可吸收到当前上下文，能够在聊天继续的原任务照常推进。

## 输出与持久保存

接收报告按“我的理解 → 对主任务的影响 → 调整后的下一步”组织，指出采用的包与版本、必须遵守的边界、冲突和未知项。无冲突且当前有合并授权时，直接维护相关交接文档，不重复请求审批；只读模式输出同样的理解和候选但不落盘。实施计划独立于源包记录，不能把主线程新增的建议塞回侧聊已确认正文。

正式目录使用 `docs/agent-handoffs/{topic}.md` 与 INDEX.md；复用既有专题结构，保留原确认包的内容或确切版本引用，接收记录另记来源、ID 映射、接收版本、用户确认依据、证据、整合变化、替代原因和待决事项。不得只存一个以后无法访问的侧聊链接。正文直接粘贴交接时，将完整确认内容持久保存到授权目录，再建立引用。

INDEX 作为小型入口，记录主题/范围、包 ID 与确认版本、正文路径、约束提示、逐项状态摘要及替代/待决关系。不把混合接受或证据状态概括成“全部已确认且已验证”。源包版本与主线程整合记录版本分别记录；只更新新增来源或实质变化，幂等重放不制造空版本。

写入前解析目标真实路径（含符号链接/重解析点），限制在已确认根目录的授权交接目录内，拒绝路径穿越；包内路径不能任意指定写入目标。重读文件基线，出现并发变化先重新核对；不冲突的调整可在已有合并授权内继续，实质决策矛盾才询问。优先临时文件原子替换，回读核对正文、版本、INDEX 引用；多文件不是整体原子事务，不能假装全部成功。

无写权限或部分失败：区分已吸收/已保存/未保存，列成功与失败路径及错误；输出失败目标对应的完整复制文本。旧文件不可读时不生成会覆盖未知历史的“完整旧文件”，改提供明确待整合的独立包或补丁所需输入。保存失败不阻塞可执行的原任务，不盲目重试、覆盖并发改动或撤销他人内容。

## 新聊天入口（首次单独确认）

已有有效入口时复用。首次设置时，先展示将加入哪个 AGENTS.md 的具体短规则，等用户确认该内容，再追加并保留原文件内容；“接收并合并”本身不授权 AGENTS.md 的首次修改。若未确认或无权限，完成正常包接收，给可复制规则，不因此卡住主任务。

可审阅的规则示例：

```markdown
## 项目交接经验
继续项目任务前，若 docs/agent-handoffs/INDEX.md 存在，先查看主题和范围，仅加载与当前任务相关的有效确认专题。实施前阅读对应完整细节，遵守理由、边界与验收要求；待决建议和被替代决策不作为当前规则。遇到确认决策矛盾时集中询问，只暂停受影响工作。不要扫描所有包。
```

此入口只帮助能读取该项目指令的后续聊天按需找回经验，不声称跨设备自动同步或所有客户端必然自动加载。

## v0.1.0 包的兼容接收

旧包仍可提取决策和来源；旧包中的 CONFIRMED 可能只指某些决策，并不证明整包受审阅。缺少整包回执且当前用户没有明确说明已确认时，仅针对缺失范围展示完整包，请用户确认一次；若用户已经明确转交整包确认事实，则保留其来源后接收，不为迁移重走审批。不要篡改旧包声称它原本使用 schema 2。
