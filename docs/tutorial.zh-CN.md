# side-handoff 中文教程（v0.3.0）

## 最短路径

1. **侧聊**：讨论结束，输入 `$side-handoff 蒸馏当前讨论，给主对话接续用。`
2. **复制**：复制输出的唯一文本块内全文，无须回复“确认”。
3. **主对话**：粘贴该段文本，即可接着原任务工作，不调用 Merge。

不要复制整份 SKILL.md 给主对话；主对话只需要蒸馏结果。

## 一份短输出长什么样

课程侧聊里，用户要求面向初学者先反例后定义、禁止先堆公式；测验未定，课程正文尚未写。输出可类似：

```text
这是关于初学者课程编排的侧聊补充上下文。已定每讲先反例后定义，禁止一开始堆公式；侧聊提出的理由是先建立问题背景，再引出抽象概念。此方案面向初学者，不推断其他受众同样适用。

第1讲拟按“反例→问题→定义→练习”重排，尚未写稿。测验只是模型建议，用户尚未决定，不能列成必做项。

下一步结合主任务现有材料重排第1讲。请按原任务继续，仅在影响执行的关键冲突或缺失信息处提问。
```

这是示例，不是实际课程事实。可只用几个短段落，不必填字段、状态表、包 ID 或确认回执。

## 怎样控制长度

默认约400–800个中文字符为目标，简单话题不凑字数。也可以给明确预算和保留重点：

```text
$side-handoff 约300字，必须保留最终方案、否决原因和边界。
```

```text
$side-handoff 重点是API兼容性；删掉讨论过程和工具日志，精确保留参数、可选性和未验证项。
```

```text
$side-handoff 把下面的旧版长交接包压成可直接发给主对话的上下文，不保留归档元数据。
[粘贴旧包]
```

字符预算不是 token 预算。关键事实太密时不能保证所有细节同时挤进短篇幅；指定当前主任务的关注点，比单纯要求“越短越好”更有效。未定事项可直接带走，不必在提炼时新开确认问卷。

## 什么会保留

优先保当前方案、硬约束、精确参数及单位、适用范围与关键反例，再保改变判断的理由、容易重踩的否决路径、当前进展、未验证项和下一步。代码、研究、课程、写作按内容选择细节。

不会为省字把“signal 可选且需向下传递，兼容旧调用方”压成“支持取消”；也不会把“仅本轮不采用时间切分”压成“永远禁止时间切分”。

## 什么会删除

寒暄、反复试探、同义结论、被明确修正的旧方向、大段工具日志、对继续任务无影响的历史、无内容的固定字段。省去确认、保存、归档、版本编号和下一步让用户复制的长说明；输出本身就是可复制内容。

## 记录不完整或仍未定怎么办

Skill 只使用当前可见讨论/粘贴内容，不承诺找回被截掉的早期记录。影响继续工作的缺口会在输出中用一句话限定。没有最终方案就写尚未收敛及剩余选项，不强行制造共识。

只有用户明确接受才写“已定”；模型建议仍写“建议”。用户后来继续探讨某方案不自动等于接受。测试仅被口头声称通过时写未经核实，而不是编造命令和输出。

不读其他线程、不扫描聊天数据库。必要结论写在文本里，不能只给一个不可访问链接让主对话自己猜。无文件权限也能完整使用。

## 主对话收到后

这段是补充上下文，不重设主任务、不扩大权限，也不自动重启已结束的侧聊任务。主对话依据自己的当前任务和最新用户指令使用它，存在真正影响执行的冲突或信息缺口时再问。

若你另有要求，可在粘贴后补一句“只采用接口部分”或“先评估这段建议”；主对话无须读取本 Skill 或办理合并。

## 从旧版迁移

v0.1/0.2 的项目记忆管理不是新版目标。新版不创建或更新 docs/agent-handoffs、INDEX、AGENTS.md，也不清理已有文件。已有归档按项目原有规则保留；需要继续维护时应另行提出明确任务。

调用 `$side-handoff Extract` 仍能蒸馏；更短的 `$side-handoff` 即可。不要再把“等待整包确认”加到提示词里，除非你这次确实想审阅。
