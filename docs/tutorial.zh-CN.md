# side-handoff 中文教程（v0.2.0）

## 你只需要做什么

1. 在打磨完成的侧聊说“用 side-handoff 准备交接”。
2. 审阅“行动摘要＋完整专题包”，修正遗漏，再确认整份指定版本。
3. 把侧聊生成的一句文件交接指令复制到主线程；不能共享文件时，连同完整包正文一起复制。
4. 主线程说明理解、影响和下一步，在原授权范围内继续。决策有矛盾时再由你裁决。

完整复制提示词与三张演示截图见 [首页](../README.md)。

## 侧聊应给你什么

摘要必须能看出采用什么、对主任务有什么影响、下一步动作，以及必须遵守的约束。完整专题保留足以复现判断的理由、适用条件、边界、反例、关键推导、否决路径、具体行动和验收方式。研究任务可有论证证据，课程任务可有教学顺序，只有代码任务才有相关代码和测试字段。

你确认的是展示出来的完整包，不是隐藏的长文。模型新补充的建议或验收方式必须在审阅版标明，不能把它当作你们原先已达成的共识。

例如讨论确定“每讲先反例后定义”，测验仍待议：

```text
确认 course@v1 的行动摘要和完整专题。先反例后定义作为确定方案；测验继续待议。
```

确认后包冻结为这个版本。新增建议或调整边界要出 draft v2，再在侧聊审阅确认；不会悄悄改写 v1。

## 文件与正文怎么选

| 条件 | 交接方式 |
| --- | --- |
| 你指定了可共享交接目录，且有权限 | 在指定目录保存确认版本，回读后传路径 |
| 未指定目录，但项目根目录已明确且双方可读 | 保存到项目 docs/agent-handoffs/inbox/，传路径 |
| 无权限、主线程不能访问、或共享性未知 | 输出完整确认包，复制正文 |

侧聊仅准备确认包，不改主线程的正式专题或 INDEX。不同版本分文件保存，同 ID 同版本若内容不同不得直接覆盖。

链接是辅助入口：你明确授权且环境有工具时可以读；只有取到完整方案和对应确认才采用。读取到摘要、占位符、截断内容时，改传现成蒸馏包；不必搬整段聊天，不扫描聊天数据库。

## 主线程接收

文件通道：

```text
$side-handoff Merge：接收并合并 course@v1；包文件：[实际共享路径]。
主任务是完成课程提纲。说明理解、影响与计划后，在原任务授权内继续。
```

正文通道：

```text
$side-handoff Merge：接收并合并下列 course@v1，整包已在侧聊确认。
说明理解、影响与计划后，在原任务授权内继续。
[粘贴完整确认包]
```

用户的本次“接收并合并”授权相关项目交接文档写入；不必主线程再复述全包让你签第二次。来源原文只在包里时，主线程记录“用户转交的侧聊确认回执”，不谎称已读取原聊天。

“看看这个包”“先出候选别保存”则是只读，即使包内自称已批准也不能修改文件。交接文档权限不新增代码实施、发消息、发表论文等权限；原主任务已授权的工作可以继续。

## 多侧聊与冲突

把几个指定包的路径或正文一起交给主线程。它先读摘要，按当前任务选相关专题，实施前再读完整细节。不应把所有历史包都加载进来。

A 确认“绝不自动重试”，B 同范围确认“网络错误重试3次”，C 是独立课程专题：主线程集中指出 A/B 冲突和影响，让你裁决；依赖该选择的工作暂停，C 继续。

现有代码还是旧超时值，而新方案已明确确认替代、没有决策矛盾：这是实现差距，主线程核查后安排修改，不再问你是否接受同一方案。若关键事实暂不可核对，只暂停依赖该事实的操作。

## 增量和旧版本

```text
$side-handoff Extract
这是旧包 course@v1 和新增讨论，请生成待审阅 v2；沿用稳定 ID，保留差异、原因与来源。
```

确认 v2 后再次交接。指令指定 v1 就读 v1，不自动追逐侧聊最新消息。重复导入相同内容不产生空版本；已有 v2 时误传 v1 不自动回退。

明确替代后，旧决定标 SUPERSEDED，记录新 ID、原因和确认来源；历史不会被擦掉。包确认版本与主线程整合记录版本分别维护。

## 新聊天的项目记忆

首次设置时，Skill 展示 AGENTS.md 的真实路径和拟加入规则。你确认具体内容后才追加，保留现有规则。入口要求先读 INDEX，再按任务读相关有效专题，不能把待议建议、被替代决定当成当前规则。

此后，能够读取该项目指令的聊天可按入口查找；不保证跨设备自动同步。没有确认入口设置时，仍完成当前包接收，你也可以手动提示：

```text
继续任务前先看 docs/agent-handoffs/INDEX.md，仅加载本任务相关的确认专题。
```

## 权限与失败

- 侧聊不能写：给完整确认正文和交接指令，不必重新审阅相同包。
- 主线程读不到包：粘贴正文；项目核对所需片段按需补充，不请求全部项目或全部聊天。
- 主线程不能保存：区分“已吸收上下文”和“未持久归档”，给完整待保存文本；聊天中可继续的任务仍推进。
- 部分写入成功：明确每个路径结果，提供失败部分修复文本；不能说整体已完成。
- 旧文件读不到：不能编造完整替换旧文件，先提供独立确认包或请求必要片段。

## 从 v0.1.0 迁移

旧版是在主线程逐次审批归档候选。新版把整包审阅放在侧聊，并认可当前用户的“接收并合并”归档授权。你仍可显式要求只读候选。

旧包某条决策的 CONFIRMED 不等于整份包已被审阅。若整包确认缺失，只补一次缺失范围的审阅；若你明确表示该整包已确认，则不为迁移重复确认。旧包版本历史保留，不改成虚构的新格式来源。
