# 验证记录与范围

## v0.2.0 — 2026-10-27

### 旧版基线

独立代理只读加载 v0.1.0，处理已在侧聊确认的课程包，用户明确要求“接收并合并，继续原授权任务”。实际输出仍要求“请确认候选 M1”，并加入无意义的代码字段。该基线复现了重复审批与非代码场景格式偏差；没有把它宣称为实际归档。

### 新版独立行为演练

独立代理加载新版 Skill 与对应模式资料，未读取 examples 中预期：

| 场景 | 实际观察 |
| --- | --- |
| Extract，无文件能力 | 展示 draft 整包；用户确认后仅更新审阅状态与回执；测验仍 PROPOSED；输出正文指令，无虚构路径 |
| A/B 已确认但规则矛盾，C 独立 | 集中询问 A/B，只暂停重试相关工作；C 的课程提纲继续，新实施建议与源包分开 |
| 链接仅返回引用占位，另有未确认 v2 | 不猜 v1、不采用 v2，请用户提供已确认包正文或可读路径 |

演练实际输出人工复核；不把文本演练当成工具权限、真实链接或模型自动发现测试。

### 隔离项目实际归档与重放

独立代理在隔离项目使用完整 course@v1 包执行“接收并合并”，实际创建确认包副本、正式专题及 INDEX，回读检查。主代理再次读取产物，核对：

- 源包与归档包逐字节相同，确认内容未实质改写。
- 正式专题将源确认内容和主线程实施计划分开，教学效果保持 UNVERIFIED。
- INDEX 与专题引用实际可达，原 AGENTS.md 未被修改。
- 同包重复导入为 NO_OP，文件哈希不变，整合版本仍为 1。
- 原授权的课程提纲在聊天继续，不要求重新批准同一包。

以上是合成课程夹具的真实文件操作，不证明所有任务或客户端行为均可靠。

### 发布检查

发布前运行官方 quick_validate.py、仓库结构/链接/PNG 检查、git diff --check；更新三张 HTML 演示页并重新截取，人工检查截图。CI 重复执行仓库结构检查；CI 不评估模型语义或实际交接流程。

尚未实测：客户端自动选择、真实无写权限拒绝、多文件部分失败、并发变更、AGENTS.md 入口确认后追加、多包冲突的实际文件更新、真实 Codex 侧聊链接的完整读取。对应预期流程见 [测试场景](../references/examples.md)。

官方格式校验和文件一致性检查通过；独立只读演练覆盖 Extract、Merge 无权限候选及路由判断。该版本采用主线程候选二次确认，已被 v0.2.0 的侧聊整包确认工作流替代。历史验证不能证明新版新增分支。
