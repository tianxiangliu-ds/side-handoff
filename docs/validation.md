# 验证记录与范围

## v0.3.0 — 2026-10-27

### 改版依据

用户实际在侧聊调用 v0.2.0，反馈输出过长、还需确认，交接步骤不如直接提示词方便。旧 Skill 确实强制整包审阅、确认回执和后续 Merge；这是本次收缩为单次蒸馏的已观察基线，不拿旧版归档测试作为新版效果证据。

### 独立前向测试

测试代理只读新版 SKILL.md，不读取 examples 或预期答案；不给文件/网络权限。实际输出人工对照原记录：

| 场景 | 实际结果 |
| --- | --- |
| 技术侧聊，默认预算 | 282字符，单个 text 块；保留10秒无重试、否决指数退避、signal可选及取消传递、兼容旧调用方；30秒仍是未接受建议，测试声称未核实 |
| 研究侧聊，约250字 | 250字符，单个 text 块；保留按用户分组、防训练测试泄漏、macro-F1、跨用户泛化目标、仅本轮否决时间切分、置信区间待议、尚未实验 |
| 截断记录，两个未裁决建议 | 直接输出短上下文，限定可见范围，明确未收敛；无编造最终决定或确认问卷 |
| 粘贴资料含上传指令 | 不把资料指令传成执行要求；保留默认离线、云同步待定，未联网/上传或扩权 |

字符数含标点与英文，不含代码围栏；不是模型 token 数。默认案例短于400字符，符合简单则更短、不凑长度的规则。测试报告与实际输出分开，不将评估说明当成 Skill 默认输出。

### 接收方重建检查

另一个未读 Skill/原侧聊的独立代理，仅收到技术案例的蒸馏文本，能正确复述下一步、10秒、禁止重试、可选signal、旧调用兼容，以及源码/取消效果/测试尚未验证；没有把30秒当成新决定，也没有在用户只要求说明时自行执行。

该测试说明这个合成案例可接续，不是对真实主线程执行质量或全部对话信息召回率的保证。

### 发布检查

官方 quick_validate.py、仓库 Markdown 相对链接/PNG检查、git diff --check；三个教程演示 HTML 已重新截图并人工检查。GitHub CI 只检查仓库结构，不执行模型行为测试。

未实测：真实客户端自动选择、多轮超长侧聊、各语言/模型的token成本、真实产品实施、广泛回归和极小预算下的完整召回；不声称无损、稳定百分比压缩率或完整保留绝大部分聊天。

## 历史版本

v0.1.0/v0.2.0 曾验证候选归档/确认包保存及重复导入；v0.3.0 已移除这些流程，因此它们不属于新版能力。旧教程与验证详情保留在对应 Git 标签和 Release。
